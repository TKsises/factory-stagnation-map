# 工程滞留マップ

工場の**工程間の滞留**（仕掛品が次の工程を待っている時間）を実データから可視化し、
金額に翻訳して、**稟議に貼れる一枚**として書き出すためのツール。

**▶ 触ってみる： https://tksises.github.io/factory-stagnation-map/**

インストール不要です。開いて「機械加工 8工程」のボタンを押せば、検証用データで全機能を試せます。

## 1. どこに何があるか

### まず読むもの

| 見たいこと | 場所 |
| --- | --- |
| **実データの仕様を何を根拠に決めたか** | [`docs/phase0-data-findings.md`](docs/phase0-data-findings.md) |
| **このリポジトリで実際に踏んだ地雷** | [`CLAUDE.md`](CLAUDE.md) |
| 何がどこまでできているか | この README の §5 |

`docs/phase0-data-findings.md` が一番大事です。列名を推測で決めていないことを、
Smart Craft 製品ソースの**ファイル経路と行番号つき**で検証できます。

`CLAUDE.md` には一般論を書いていません。**ここで実際に起きた事故だけ**が載っています
（滞留率が薄まっていた件、CSV解析が30倍遅かった件、予定と実績の取り違えなど）。

### コード（`src/`）

下の層ほど依存が少なく、上の層が下を使います。**逆向きの依存はありません。**

| 層 | 場所 | 役割 |
| --- | --- | --- |
| **domain** | `src/features/stagnation/domain/` | 計算のすべて。画面を知らない純粋関数。テストはここに集中 |
| **render** | `src/features/stagnation/render/` | 形と座標変換。SVG（画面）と Canvas（書き出し）が**共有**する |
| **components** | `src/features/stagnation/components/` | 画面。パネル1つ＝1コンポーネント |
| **functions** | `src/features/stagnation/functions/` | 稟議用PNGの書き出し（dataURL を返す純粋関数） |
| **app** | `src/App.tsx` | 各層をつなぐだけ |

#### domain の中身（読む順）

| ファイル | 何をするか |
| --- | --- |
| `types.ts` | データモデル。設定・実データ・一時状態を型で分ける |
| `csv.ts` | CSV解析（自前・RFC4180）と文字コード判定（UTF-8 / BOM / Shift_JIS） |
| `datetime.ts` | 日時と数値の解析。読めないものは `null`（0にしない） |
| `storage.ts` | `normalizeConfig()`。外から入る設定の**唯一の入口** |
| `mapping.ts` | 列マッピングと診断。**「予定」を実績として掴まない**のがここ |
| `lots.ts` | 行 → ロット単位への組み立て |
| `calendar.ts` | 暦時間と稼働時間 |
| `gaps.ts` | 工程間の滞留。欠損を4段階（実績/近似/日付のみ/除外）で記録 |
| `metrics.ts` | 集計。**指標の計算元はここ1箇所だけ** |
| `money.ts` | 金額。凍結額・1日あたり製造原価・削減試算 |
| `lotView.ts` | ロット一覧の行（帯と工程明細） |
| `layout.ts` / `layoutLink.ts` | レイアウト取り込みと、工程との接着 |
| `theme.ts` | 色・間隔・**断定表現を出さないための文言集** |

テストは各ファイルの隣（`*.test.ts`）にあります。**309件**。

### 検証用データ（`public/fixtures/`）

`public/` に置いてあるので、**配信サイトからもそのまま読めます**（アプリのボタンで読み込めます）。

| ファイル | 工程 | ロット | 滞留率 | 何を試すか |
| --- | --- | --- | --- | --- |
| `case1-machining-8processes.csv` | 8 | 2,377 | 82% | **主力**。まずはこれ |
| `case1-machining-8processes-sjis.csv` | 8 | 2,377 | 82% | Shift_JIS で文字化けしないか |
| `case2-assembly-4processes.csv` | 4 | 900 | 65% | **健全な工場**。いつも問題ありと言う道具ではないことの確認 |
| `case3-complex-12processes.csv` | 12 | 1,500 | 81% | 工程飛ばし・日付のみ・欠損が多い |
| `broken-no-actual-columns.csv` | — | — | — | 予定列しか無い。「計算できません」と出るのが正しい |
| `broken-header-only.csv` | — | — | — | ヘッダーだけ。落ちないこと |
| `layout-sample.json` | — | — | — | 検証用レイアウト（case1 の設備コードに対応） |

作り直すとき（乱数の種は固定なので、何度実行しても同じものが出ます）:

```bash
npm run fixtures        # CSV 3種類 + Shift_JIS + 敵対的ケース
npm run layout-fixture  # レイアウト
```

## 2. 手元で動かす

```bash
npm install
npm run dev
```

開発サーバーは **5176番ポート**。他のアプリ（レイアウト旧版5173・スロット分析5174・レイアウトv2 5175）とぶつかりません。

## 3. 確かめる

```bash
npm run typecheck
npm test
npm run lint
```

**型が通った・テストが緑は、動作確認の代わりになりません。** 画面に出るものは実ブラウザで確かめます。

## 4. 使い方（画面の流れ）

1. CSVを読み込む（ドラッグ、またはサンプルのボタン）
2. **滞留マップ**が出る ← ここが主役
3. 気になった**山**（工程間）や**工程の箱**を押すと、そこだけの数字が出る
4. 必要になったら、下の折りたたみを開く
   - 原価を入れて金額を出す
   - 提案用の一枚を書き出す（流れの図 / レイアウト重ね図）
   - ロットを1件ずつ追う
   - 工場レイアウトに重ねる
   - この数字の根拠（データ品質）
   - 列の対応づけを直す

最初から全部は出しません。**押したものだけ**が出ます。

### まだ満たしていない完成条件

**実際の工程実績CSVで動かしていません。** いま動かしているのはすべて合成データです。
Smart Craft のソースを読んで「何を出力する仕様か」は確定しましたが、
**実データの空欄率だけは実物を読ませないと分かりません**（アプリの診断パネルが測って出します）。

これが埋まるまでは「完成」と言えません。

## 6. 方針

- **バックエンドを持たない。** 読み込んだCSVはブラウザの中だけで処理し、外に出さない
- 保存するのは設定だけ（列マッピング・原価・稼働カレンダー・レイアウト対応表）
- 描画ライブラリ・CSV解析ライブラリを入れない（実行時の依存は React だけ）
- **計算できないものを 0 にしない。** 除外件数として表示する
- **断定表現を出力しない。**「削減できます」ではなく「御社の入力値に基づく試算です」
