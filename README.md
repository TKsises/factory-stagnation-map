# 工程滞留マップ

工場の**工程間の滞留**（仕掛品が次の工程を待っている時間）を実データから可視化し、
金額に翻訳して、稟議に貼れる一枚として書き出すためのツール。

## 動かす

```bash
npm install
npm run dev
```

開発サーバーは **5176番ポート**（`~/.claude/launch.json` に `factory-stagnation` として登録済み）。
他のアプリ（レイアウト旧版5173・スロット分析5174・レイアウトv2 5175）とぶつからない。

## 検証用CSVを作り直す

実データが手に入るまでの足場。実際の出力列・書式をそのまま再現している。

```bash
npm run fixtures
```

`fixtures/` に出る。**Shift_JIS 版もこのスクリプトが作る**（外部ライブラリも PowerShell も不要）。

レイアウトは `npm run layout-fixture` で作る。

| ファイル | 用途 |
| --- | --- |
| `case1-machining-8processes.csv` | **主力**。機械加工8工程 / 2,377ロット / 19,016行。滞留率82% |
| `case1-machining-8processes-sjis.csv` | 同じ内容の Shift_JIS 版（文字化けしないか） |
| `case2-assembly-4processes.csv` | 組立4工程 / 900ロット。**健全な工場**（滞留率65%、突出した工程間なし） |
| `case3-complex-12processes.csv` | 複合加工12工程 / 1,500ロット。工程飛ばし・欠損が多い |
| `broken-no-actual-columns.csv` | 予定列しか無いCSV。「計算できません」と出るべき |
| `broken-header-only.csv` | ヘッダーだけ。落ちないこと |
| `layout-sample.json` | 検証用のレイアウト（case1の設備コードに対応） |

case2 を入れてあるのが大事で、**このアプリが「いつも問題ありと言う道具」ではない**ことを
確かめられる。1つのデータだけで作ると、そのデータでしか動かないものが出来上がる。

## 確かめる

```bash
npm run typecheck
npm test
npm run lint
```

**型が通った・テストが緑は動作確認の代わりにならない。** 画面に出るものは実ブラウザで確かめる。

## 方針

- バックエンドを持たない。読み込んだCSVはブラウザの中だけで処理し、外に出さない
- 保存するのは設定だけ（列マッピング・原価・稼働カレンダー・レイアウト対応表）
- 描画ライブラリ・CSV解析ライブラリを入れない
- 計算できないものを 0 にしない。除外件数として表示する
